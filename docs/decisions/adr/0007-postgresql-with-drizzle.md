# ADR-0007: PostgreSQL with Drizzle ORM

Status: Accepted
Date: 2026-09-30
Related: [database.md](../../specs/database.md), ADR-0010

## Context

The data is relational (users, memories, assets, albums, memberships, permissions) and needs transactions, constraints, and analytical queries. The owner chose PostgreSQL and Drizzle.

## Decision

- **PostgreSQL 17+** is the only primary datastore (it also hosts the job queue, ADR-0010).
- **Drizzle ORM** with SQL-like, type-safe queries. Schemas are colocated with their modules. Migrations are generated by drizzle-kit, reviewed, committed, and forward-only.
- Fields used for analytics and filtering are **typed columns**. Full capture metadata is also kept as `jsonb` for completeness.

## Alternatives

- **Prisma:** heavier runtime and generated client; less direct SQL control.
- **Kysely / raw SQL:** viable, but Drizzle gives both schema definition and migrations.
- **Document DB:** a poor fit for permissions and relational queries.

## Consequences

- Schema tests run against a real Postgres in CI (Testcontainers).
- Complex analytics may need raw SQL via Drizzle's `sql` template. That's acceptable.
- Adding pgvector for AI later is an extension, not a new datastore (it needs its own ADR).
